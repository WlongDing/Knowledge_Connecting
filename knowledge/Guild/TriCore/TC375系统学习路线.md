# TC375 / TriCore 系统学习路线

## 1. 学习目标与默认条件

目标是让已有 Cortex-M4/M7 经验的开发者，能够独立完成：

1. 从复位入口追踪到各核 `main()`；
2. 解释并修改启动配置、BMHD、CSA、栈、BIV/BTV；
3. 读懂链接文件和 `.map` 文件，控制代码/数据落点；
4. 独立完成外设中断到指定 CPU/DMA 的路由；
5. 理解并维护 AUTOSAR `MemMap.h`；
6. 处理多核共享数据、受保护寄存器、Cache、Trap 与基本安全机制；
7. 最终搭建一个可调试、可解释、可检查内存布局的三核小型工程。

默认使用 TC375 + AURIX Development Studio（ADS）+ iLLD 示例工程。若项目使用 TASKING、HighTec、GHS 或 AUTOSAR MCAL，概念不变，但启动文件、关键字和链接语法会不同。

建议周期：10 周，每周 6～8 小时。若每周只有 3～4 小时，可按 20 周推进。

## 2. 先建立 Cortex-M 到 TriCore 的映射

| Cortex-M4/M7 认知 | TC375 / TriCore 对应物 | 必须注意的差异 |
|---|---|---|
| Reset_Handler | Boot Firmware + Application Startup Software | 复位后先运行芯片 Boot Firmware，再进入用户启动地址；不能只从一个向量表首项理解启动 |
| MSP / PSP | A10 用户栈、ISP 中断栈，以及 CSA 链 | 函数/中断上下文大量依赖 CSA，不是简单压入当前栈 |
| VTOR + NVIC | BIV/BTV + Interrupt Router + SRC/SRN | 普通中断与 Trap 分表；外设请求还要选择服务提供者和优先级 |
| IRQn | 外设 Service Request Node | “外设源编号”与“CPU 向量优先级”不是一一固定映射 |
| NVIC priority | SRC.SRPN + CPU 当前优先级 | SRPN 同时参与仲裁和向量地址选择；0 保留 |
| `.isr_vector` | 每核 Interrupt Vector Table / Trap Vector Table | 每个 CPU 可有自己的 BIV/BTV，也可按系统设计共享 |
| SRAM / TCM | DSPR / PSPR / DLMU / LMU | 有每核本地与全局地址视图，其他主机访问需使用正确全局地址 |
| SCB fault handlers | 8 类 Trap + TIN | Trap 与普通中断机制分离，TIN 在 D15 中标识具体原因 |
| MPU / privilege | 多组保护寄存器 + Supervisor/User 模式 | 还要理解 ENDINIT、Safety ENDINIT 和访问保护 |
| linker script | LSL/链接描述文件 + map 文件 | 语法由工具链决定；启动代码依赖链接器导出的 CSA、栈、向量表等符号 |
| CMSIS/HAL | iLLD / MCAL | iLLD 更接近寄存器；MCAL 还叠加 AUTOSAR 配置和 MemMap |

## 3. 10 周路线

### 第 0 周：工具和资料闭环（半周）

学习内容：

- 确认准确器件 OPN、silicon step、开发板和调试器；
- 安装 ADS，导入与板卡匹配的官方 Blinky；
- 保存 datasheet、TC3xx User Manual Part 1/2、TriCore Architecture Vol.1/2、TC37x Appendix、Errata、AP32381；
- 学会生成并定位 ELF、HEX、MAP、反汇编和链接日志。

实践与验收：

- 工程能 Build、Flash、Debug；
- 能指出 `Cpu0_Main.c`、启动配置、BMHD、两个链接文件和 `.map` 文件；
- 记录 ADS、编译器、iLLD、板卡、芯片 step 的版本。

### 第 1 周：TriCore CPU 编程模型与 CSA

学习内容：

- TC1.6.2P 的 A0～A15、D0～D15、PC、PSW、PCXI、FCX、LCX、ICR；
- 上下文的 upper/lower context；
- `CALL/RET`、中断、Trap 与 CSA 链的关系；
- User/Supervisor 模式、A10 栈与 ISP；
- 16/32 位指令、load/store 与小数据寻址的基本概念。

实践与验收：

- 在调试器观察 A10、PCXI、FCX、LCX；
- 单步一次普通函数调用，画出栈和 CSA 分别保存什么；
- 故意减小 CSA 或制造深递归，在受控示例中观察相关 Trap。

### 第 2 周：TC375 内存体系与地址视图

学习内容：

- PFlash、DFlash、DSPR、PSPR、DLMU、LMU、Cache；
- 每核本地地址与全局地址；CPU、DMA、其他 CPU 看到的地址差异；
- cached/uncached 别名、对齐、ECC 初始化的基本要求；
- 代码、常量、已初始化数据、零初始化数据、NOINIT、栈、CSA 的用途。

实践与验收：

- 从手册和 `.map` 文件画出本工程的实际内存图；
- 放置一个变量到 CPU0 DSPR、一个共享变量到 LMU；
- 证明 CPU1 或 DMA 访问 CPU0 本地 RAM 时应使用何种地址视图。

### 第 3 周：复位、Boot Firmware、BMHD 与启动流程

学习内容：

- PORST、系统复位、应用复位、CPU 复位的差异；
- Boot Firmware 的职责；BMHD/BMI、启动模式和用户起始地址；
- CPU0 默认启动、CPU1/CPU2 的 HALT→RUN；
- 用户启动软件的阶段：早期 PSW/复位判断、CSA/栈、时钟与 Flash wait state、Cache、BIV/BTV、C 初始化、其他核启动、进入 `main()`；
- 看门狗 ENDINIT 与 Safety ENDINIT 的基本意义。

实践与验收：

- 从 `_START`/工具链入口单步到 `Cpu0_Main.c`；
- 写出“谁设置 SP、CSA、BIV、BTV，谁清零 BSS，谁复制 DATA”；
- 修改一个安全的 SSW 配置项并从寄存器和 `.map` 两侧验证。

### 第 4 周：链接文件与启动代码联调

学习内容：

- 工具链输入 section、输出 group、memory region、符号、对齐和填充；
- `Lcf_Tasking_Tricore_Tc.lsl`、`Lcf_Gnuc_Tricore_Tc.lsl` 的角色；
- 每核 USTACK、ISTACK、CSA、INTTAB、TRAPTAB；
- A0/A1/A8/A9 小数据区；
- copy table / clear table 以及 RUN address 与 LOAD address；
- 从源文件的 section attribute 追踪到 ELF 和最终地址。

实践与验收：

- 将一个函数放入 PSPR 运行；
- 将一组常量放到指定 PFlash；
- 建立 NOINIT 区并验证暖复位后的预期行为；
- 用 `.map`、反汇编和运行时地址三重验证。

### 第 5 周：中断路由、优先级和 Trap

学习内容：

- 外设事件 → SRN/SRC → Interrupt Router/ICU → CPU/DMA；
- SRC 中的 TOS、SRPN、SRE、SRR；
- BIV、向量间距、每核向量表和 ISR 声明宏；
- 全局使能 ICR.IE、嵌套和当前 CPU 优先级；
- BTV、8 个 Trap Class、TIN、同步/异步 Trap。

实践与验收：

- STM 周期事件分别路由到 CPU0 与 CPU1；
- 调整两个中断的 SRPN，观察抢占次序；
- 将一个服务请求路由给 DMA，理解“服务提供者不一定是 CPU”；
- 人为触发一个安全可恢复的 Trap，读取 Class 和 TIN。

### 第 6 周：多核启动、共享内存和同步

学习内容：

- 每核启动入口、同步事件和启动屏障；
- DSPR/PSPR 的核归属与跨核访问；
- LMU/DLMU 共享数据布局；
- 原子操作、spinlock、内存屏障、Cache 可见性；
- 多核变量的所有权与“单写多读”设计。

实践与验收：

- CPU0 初始化系统，CPU1 采集，CPU2 处理；
- 用共享环形缓冲区传递数据；
- 对共享结构加入对齐、同步和所有权说明，并通过压力测试。

### 第 7 周：MemMap 与 AUTOSAR 内存抽象

学习内容：

- `Compiler.h` / `Compiler_Cfg.h` / `MemMap.h` 的职责边界；
- `MODULE_START_SEC_*` 与 `MODULE_STOP_SEC_*`；
- 代码、常量、INIT/CLEARED/NOINIT、按位宽或按核区分的 section；
- 编译器 pragma/attribute 如何产生 ELF section；
- 链接文件如何把逻辑 section 放入 PFlash、DSPR、LMU、PSPR；
- 常见错误：START/STOP 不配对、嵌套 section、默认 section 泄漏、命名不一致、NOINIT 被清零。

实践与验收：

- 自己实现一个最小 `App_MemMap.h`；
- 把快函数映射到 PSPR，把跨核共享数据映射到 LMU；
- 用预处理输出、ELF section 表、`.map`、运行时地址完成四层验证。

核心链路：

```text
App_START_SEC_CODE_FAST
        ↓ include MemMap.h
编译器 pragma / attribute 切换 section
        ↓
目标文件中的 .app_code_fast 输入 section
        ↓ 链接文件 placement
PSPR 中的输出 section / 固定地址
        ↓ 启动 copy table
上电时从 Flash 复制，随后在 PSPR 执行
```

### 第 8 周：常用外设与 DMA

学习内容：

- Port、STM/GTM、ASCLIN、MCMCAN、EVADC；
- 模块时钟、复位、受保护寄存器和 SRC；
- DMA channel、trigger、transaction 与完成中断；
- iLLD 调用与寄存器字段之间的对应关系。

实践与验收：

- 每个外设先用 iLLD 跑通，再对照寄存器解释关键配置；
- 完成“ADC/通信接收 → DMA → 共享缓冲区 → 另一核处理”。

### 第 9 周：调试、保护与安全基础

学习内容：

- Trap 定位、PCXI/CSA 链、栈水位、map/反汇编联合分析；
- CPU/总线/内存保护、ENDINIT、看门狗；
- ECC、SMU、MBIST/LBIST 的定位和适用阶段；
- Errata 与 silicon step；
- 启动时间、中断延迟和热点代码的测量。

实践与验收：

- 建立一页故障定位清单；
- 对非法地址、CSA 耗尽、看门狗、ECC/SMU 示例做可控实验；
- 所有实验注明“开发实验”和“量产安全策略”的边界。

### 第 10 周：综合工程

建议项目：三核 CAN 数据采集与监控节点。

- CPU0：启动、时钟、看门狗、MCMCAN、系统状态；
- CPU1：ADC/传感器采集和 DMA；
- CPU2：滤波、诊断和统计；
- LMU：共享环形缓冲区；
- DSPR：各核私有工作区；
- PSPR：一个经测量确认的关键函数；
- 中断：至少两个 CPU 服务者和一个 DMA 服务者；
- MemMap：CODE、CONST、INIT、CLEARED、NOINIT、SHARED 六类；
- 交付：启动时序图、内存图、中断路由表、链接 map 审查表、Trap 记录表。

验收标准：不看示例也能解释从外设事件到 ISR 的完整链路，从 C 对象到物理地址的完整链路，以及从复位到三核进入应用的完整链路。

## 4. 每周固定学习节奏

每周采用同一个闭环：

1. **读手册 90 分钟**：只读本周直接相关章节，记录寄存器/术语；
2. **读启动或 iLLD 源码 90 分钟**：顺着调用链，不横向漫游；
3. **板上实验 2～3 小时**：必须至少观察一个寄存器、一个地址、一个运行现象；
4. **产出一张图/一张表 60 分钟**：如启动时序、内存图、中断路由表；
5. **口述验收 30 分钟**：不看资料回答本周的三个关键问题；
6. **复盘 30 分钟**：记录疑问、失败实验、下周入口。

不要把目标设为“读完手册”。真正的学习单位应是“能解释一条执行链，并用调试器和 map 文件验证”。

## 5. 推荐资料阅读顺序

1. TC375 器件 datasheet 与 TC37x Appendix：确认你的具体芯片有什么；
2. AP32381 Startup and Initialisation：建立复位到应用的主线；
3. TriCore Architecture Vol.1：编程模型、CSA、中断、Trap；
4. TC3xx User Manual Part 1/2：按模块查阅，而非顺序通读；
5. 官方 AURIX Code Examples：实验入口；
6. iLLD 文档与源码：把 API 映射到寄存器；
7. 所用编译器的 linker/locator 手册：学习具体 LSL/链接脚本语法；
8. AUTOSAR Memory Mapping 规范：最后建立跨编译器、跨模块抽象。

## 6. 学习记录模板

每个主题都回答下面六个问题：

1. 事件从哪里产生？
2. 经过哪些硬件模块和寄存器？
3. 启动代码或驱动在哪里配置它？
4. 链接器为它提供了哪些地址或符号？
5. 如何用调试器、ELF 和 `.map` 验证？
6. 与 Cortex-M 的同类机制有什么本质差异？
